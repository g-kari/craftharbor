# Windows起動後の自動復帰

開発版の機能です。既存の配布済み0.4.0-previewにこの機能が追加されるわけではありません。

## 使い方

1. 通常の管理画面でJava・サーバー・必要な公開接続を導入し、起動できることを確認します。
2. 復帰させたいプロファイルの「運用・予約」で「公開接続も起動する」と待機秒数（0〜600、初期30秒）を選び、「登録・更新」を押します。
3. WindowsのUACと認証ダイアログで承認・入力します。必要なのはそのWindowsユーザーのパスワードで、Windows HelloのPINではありません。入力内容をチャットへ送る必要はありません。
4. 次のWindows起動時に同じアカウントの通常権限で常駐ホストが開始します。Windowsへのサインインは不要です。登録した時点では起動・停止・再起動しません。
5. 後から管理画面を開くと同じサーバー・公開接続へ再接続します。「状態を確認」でWindowsの最終実行結果と自動復帰の最終記録を確認できます。

登録はプロファイルごとです。保存先を移した場合は旧登録を解除して新しい場所から再登録します。「登録を解除」は次回の自動起動だけを解除し、今動いているサーバーは停止しません。「今回の自動復帰を中断」は起動準備・再試行を止めます。稼働中のサーバーを止める操作は「保存して停止」です。

## 権限と認証

- WindowsのBootTrigger登録に限り管理者権限が必要です。実行タスクは `RunLevel=LeastPrivilege` / `TASK_LOGON_PASSWORD` です。SYSTEMや管理者権限でMODを実行しません。
- UACで別の管理者ユーザーへ切り替える方式には対応していません。元のWindowsユーザーとSIDが一致しなければ登録を拒否します。
- パスワードは登録時にWindows Task Schedulerへ渡します。CraftHarborのJSON、コマンドライン、ログには保存しません。ネイティブ認証画面の入力バッファは使用後に消去します。COM呼び出しに伴う一時的なマネージド文字列は生成されます。
- S4Uはネットワークや暗号化ファイルへアクセスできないため使用しません。既存のユーザープロファイル・接続認証を利用します。
- アカウントにパスワードがない場合、組織ポリシーでバッチログオンが禁止される場合、パスワード変更後には実行できないことがあります。パスワード変更後は再登録してください。
- Windowsのセキュリティ設定、実行ポリシー、自動サインインは変更しません。

根拠: [TaskFolder.RegisterTaskDefinition](https://learn.microsoft.com/en-us/windows/win32/taskschd/taskfolder-registertaskdefinition)、[Task security contexts](https://learn.microsoft.com/en-us/windows/win32/taskschd/security-contexts-for-running-tasks)。

## 起動と停止の動作

保存済みプロファイルのJAR/Java引数ファイル、Java設定、メモリ共有予算、距離設定、保存済み音声接続設定を使用します。初回セットアップ、EULA同意、トンネルの新規作成は自動化しません。

- EULA、Java、起動ファイル、ポート競合、メモリ予算を確認します。バックアップ・復元と起動準備は共有ロックで排他し、管理画面からも自動復帰の準備中に設定変更しないよう確認します。
- 自動復帰の失敗は30秒間隔で最大3回試行します。起動完了は最大10分待ちます。長時間起動中のプロセスを勝手に強制終了しません。
- サーバーのDone確認後に、選択した公開接続を起動します。playit.gg・ngrokは事前の認証が必要です。直接公開では別プロセスを起動しません。
- 画面操作が必要なポート開放ツールは対象外です。サーバーだけの自動復帰は利用できます。
- 公開接続のプロセス起動は外部からの接続成功を保証しません。ネットワークやサービス側の障害はコンソールで確認します。
- 手動停止は優先され、そのWindows起動中の復帰再試行をキャンセルします。次回のWindows起動では、登録が有効なプロファイルを再び起動します。
- 毎日の予定再起動は常駐ホストが人数確認・保存・完全バックアップ後に実行します（[運用機能](OPERATIONS.md)）。異常終了時の再起動・Discord通知は管理画面の機能です。この起動タスクは常時クラッシュ監視サービスではありません。
- 常駐ホストの重複防止とメモリ予約はWindowsセッションをまたぐ同一ユーザーのGlobalミューテックス、管理通信はそのユーザーのみを許可する名前付きパイプを使用します。
- OSの強制終了・電源断でワールド保存が完了する保証はありません。更新前の保存とバックアップは引き続き必要です。

`boot-options.json` は有効状態、待機秒数、公開接続の選択、所有者SIDのみです。`boot-status.json` は最後の起動結果です。これらはローカルの運用データで公開しません。

インストーラーはサインイン前のホストも更新ロックで検出します。アンインストーラーは同じインストール先・所有者に属する起動タスクのみ解除します。ワールド・設定・バックアップは残します。ポータブル版の削除前には画面から起動タスクを解除してください。

## 検証

`tools/check-boot.ps1` はWindows CIでのみ使用する人工プロセスの検証です。Task Schedulerの実COMオブジェクトでBootTrigger・通常権限・バッチログオン・実行時間制限なし・登録時トリガーなしを確認します。人工Java/トンネルで、画面なし起動、同一PIDへの再接続、重複ホスト抑止、サーバーと公開接続の独立停止、再試行キャンセル、EULA拒否、ポート競合、無関係な設定の維持を検証します。

既存のcore・integration・Java・9画面のUI・インストーラー検証も実行します。検証中に実際の起動タスク登録、パスワード入力、Windows再起動、本物のMinecraftや公開トンネルの起動は行いません。

**実アカウントでの登録、別セッションからの接続、Windows再起動後のサインイン前自動復帰は未検証です。** ユーザーの依頼により、この開発ではPC再起動やインストール切替を行いません。
