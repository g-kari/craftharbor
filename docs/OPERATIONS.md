# 接続診断・更新試験・参加者MOD照合・常駐予約

開発版の機能です。配布済みv0.4.0-previewには含まれません。実Minecraft、外部参加者、すべてのMOD/プラグインとの互換性は保証しません。

## 友達が入れないとき

メトリクスの「接続を診断」から「診断を実行」を選びます。設定済みJavaの`-version`確認、管理下サーバーの状態、ローカルTCPのMinecraftステータス応答、公開接続プロセス、保存済み公開先への同じPCからのステータス応答、許可設定、既存の音声MOD検出をまとめて表示します。

- Minecraftの版・人数だけを読み、MOTDや参加者名、未編集ログを外部送信しません。
- 公開先がこのPCから応答しても、別回線の参加者から到達できる証明ではありません。
- UDP待受は所有プロセスまで確認していません。UDP無応答を故障と断定しません。ゲームTCPと音声UDPは別に確認してください。
- Java版はパックの要求版と自動照合しません。パック配布元の指定を確認してください。
- サーバー起動、トンネル作成、ルーター・ファイアウォール・認証設定変更は行いません。

## MODパック更新のお試し環境

「MOD・導入案内」→「更新を試す」を開きます。

1. 既存のURL取り込み等で、新版パックを**別のワークスペース**へ導入します。必要な初期セットアップは自分で完了させ、サーバーと公開接続を停止します。
2. 本番のサーバー・公開接続も停止し、更新元と新しい保存先を指定して「コピーを作成」。旧本番ワールドのコピーと新版ランタイムを組み合わせます。原本/更新元は上書きしません。
3. お試し環境を別画面で開いて起動し、自分でゲーム接続、ワールド、MODを確認します。起動完了中に「起動結果を記録」し、その同じホスト・同じ起動を「保存して停止」してください。試験画面は閉じず、その画面から「更新を試す」を開きます（停止後に画面を閉じるとホストが終了し、結果の同一性を確認できません）。
4. 旧原本のWindows自動復帰を既存画面で無効化・解除し、旧原本の管理画面を閉じます。有効な旧起動タスクが残る/状態が不明な場合は切替を止めます。試験画面で、試験構成の署名、正常終了、停止状態を確認後、チェックと確認ダイアログを通して「このコピーを本番に切替」。新しい保存先を本番として開きます。旧原本はそのままです。
5. 戻すときは、新しい環境を停止して「旧原本へ戻す」。新しい保存先は削除しません。

### 安全側の既定値と制限

- 本番と異なるゲームポート、`127.0.0.1`待受、公開トンネルなし、RCON/query無効。対応する既存音声MODは別のローカルUDPポートへ変更します。未初期化の音声設定は作成を止めます。プラグイン独自の待受/通信は網羅しません。
- 原本と更新元の管理画面/常駐ホスト/ポートと共有maintenance lockを確認します。リンク・ジャンクション・外部`level-name`は拒否します。別ツールからの同時操作は避けてください。
- コピー容量と少なくとも1 GiBの余白、OSと他サーバーの予約分を残した4 GiB以上のヒープ予算を確認します。起動時にも既存のRAM予算を再計算します。
- 追加/削除/変更MODはファイルハッシュの差です。互換性判定ではありません。
- 公開接続の資格情報、保存済み公開先、Windows自動復帰・予約設定は引き継ぎません。本番切替ではゲーム待受/ポートのみ旧本番へ合わせ、公開方法・音声・予約は既存画面で別途設定します。
- 起動記録後にJAR、実起動ターゲット、ライブラリー、MOD、主要起動設定が変わると再試験が必要です。全設定/依存関係の完全検証ではありません。
- ワールド変換は不可逆な場合があります。**切替後に進んだワールドは、戻す旧原本へ反映されません。** 完全バックアップと原本を保持してください。
- 取消/失敗時の部分コピーは「受入済みの環境」にしません。エラーに示す一時コピーを確認してから整理できます。原本は削除しません。

## 参加者MOD構成照合

「MOD・導入案内」→「参加MOD照合」でサーバーMODまたは主催者の構成JSONを読みます。参加者の`mods`フォルダーまたは同形式JSONを選んで比較します。JARは実行せず、メタデータとハッシュだけを読みます。

| 役割 | 不足の扱い |
|---|---|
| `required` | 主催者が明示した参加必須MOD。不足・版違いを表示 |
| `server-only` | 参加者への導入を要求しない |
| `client-only` | クライアント専用として区別。任意性は配布元/主催者に確認 |
| `unknown` | 判定保留。自動的に必須と決めない |

Fabricの`environment`は実行する側であり、両側対応だから参加必須とは限りません。Forge/NeoForgeの通常の`[[mods]]`も既定はunknownです。未対応形式、入れ子MOD、解決不能な版、重複IDは保留にします。依存関係、ローダー、設定やネットワーク互換性は別途確認してください。

構成JSONはMOD ID・版・役割・ハッシュ・指定配布リンクとゲーム/パック版だけです。JAR・設定・ワールド・絶対ファイルパス・参加者名は含めません。Modrinth/CurseForgeのMODページまたは公式GitHubへの認証情報/queryのないHTTPSリンクを指定できます。メタデータのリンクが正規配布元かは自動証明しません。主催者が確認して共有してください。

メタデータの根拠: [Fabric公式仕様](https://docs.fabricmc.net/develop/loader/fabric-mod-json)、[Forge公式仕様](https://docs.minecraftforge.net/en/latest/gettingstarted/modfiles/)。ハッシュ一致は互換性の証明ではありません。

## 管理画面を閉じても動く毎日の予約

「運用・スケジュール」で毎日の時刻を選び、運用設定を保存します。既存の予約設定を常駐ホストで読み、GUI側の二重予約処理は使いません。サーバー起動で常駐ホストを開始した後は、管理画面を閉じても実行します。停止中のサーバーを予約だけで自動起動しません。

1. PCのローカル時刻が予約時刻を過ぎ、起動完了なら、新しい`list`応答で人数を確認します。
2. 無人なら60秒予告し、直前にもう一度人数を確認します。人数あり/不明は延期し、予約から30分を超えると当日は見送ります。未知のログ書式は無人扱いしません。
3. 無人を再確認後、`save-all flush`→`stop`で保存停止。終了を待って完全ZIPを作り、既存のJava/メモリ/次回設定チェック後に一度だけ再起動します。
4. 停止に時間がかかる・異常終了・バックアップ/起動失敗の場合は強制終了や無限再試行をせず、安全側で止めます。管理画面の予約結果と常駐ログを確認してください。

「保存して停止」「全部停止」「予約処理を中断」は当日の予約より優先します。処理中の停止でも再起動を取り消します。予定日ごとの実行claim/取消結果を保存し、ホスト再起動や時計巻戻しで同じ予約を繰り返しません。途中中断で状態が不明なときは自動再実行しません。ディスク障害等で取消記録を保存できなかった場合は現ホスト内の中断だけを確認し、警告を表示します。ホスト/PC再起動後の取消保持は保証できないため、予約状態を再確認してください。

PC停止/スリープ中は動きません。サーバーの実際の保存成功、OSスリープからの復帰、独自MODの人数ログは実環境で確認してください。Discord通知と既存の異常終了時再起動は引き続き管理画面の起動中のみです。公開トンネルを新規作成/再設定しません。次回設定でゲームポートを変える場合は、公開側の転送先も別途確認してください。

## 検証

`tools/build.ps1`、`--core-check`、既存の統合/設定/起動/UI/Javaチェックに加え、`tools/check-schedules.ps1`が合成常駐ホスト・偽サーバーで予約を確認します。UIプレビューは合成データで、診断の実通信・更新コピー・実サーバー起動は行いません。チェック結果と実環境未検証の範囲を分けて扱ってください。
