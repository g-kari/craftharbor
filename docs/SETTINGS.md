# サーバー設定と参加許可

## 稼働中に設定を保存する

「サーバー設定」の基本設定・プロファイルは、停止中でも稼働中でも保存できます。画面は「保存済み・再起動待ち」を表示し、再起動するまでは現在のゲーム設定、接続ポート、バージョンを維持します。管理アプリを閉じて開き直しても編集欄には保存済みの次回設定が戻ります。

変更はワークスペースの `pending-server-settings.json` に保管します。稼働中の `server.properties` は編集しないため、サーバーが終了時に古い設定を書き戻しても保存した変更は失われません。通常の起動とWindows起動タスクの両方が、停止・ポート競合を確認してから変更を反映します。ファイル更新前のコピーは `server.properties.before-settings.bak` に残します。未編集の設定や認証設定は維持します。

プロファイルのJavaパス・JAR/引数ファイル・バージョン・接続ポートも次回起動用です。Javaや起動ファイルを実際に導入・更新する機能ではありません。接続ポートを変更した場合、トンネル側の転送先も合わせて設定してください。

距離・Javaの自動調整は従来どおり次回起動用に保存します。距離の推奨値は[性能設定](PERFORMANCE.md)を参照してください。保存だけでサーバーやPCを自動再起動することはありません。

## 停止中のホワイトリスト

「参加者・権限」の参加許可は停止中も追加・解除できます。

- 稼働中はサーバーへ `whitelist add/remove` コマンドを送ります。実際の結果はコンソールで確認します。
- 停止中の追加では、オンライン認証が有効なら入力した名前をMojangのHTTPS APIへ1回問い合わせ、返された名前とUUIDを検証します。認証トークンは不要です。名前が見つからない場合や通信エラーではリストを変更しません。
- オンライン認証を明示的に無効化している既存サーバーでは、その方式の名前由来UUIDを生成します。CraftHarborが認証を無効化することはありません。
- 解除では通信せず、指定した名前の許可だけを除去します。
- ファイル更新直前に起動状態をもう一度確認し、起動・復元などとの競合を防ぎます。応答待ちの間にサーバーが起動した場合は稼働中のコマンドへ切り替えます。
- `whitelist.json` は一時ファイルから原子的に置き換え、直前の内容を `whitelist.json.before-manager.bak` に残します。壊れたJSONを空リストとして上書きしません。

許可リストの有効・無効やOP権限は自動変更しません。サーバーのポリシーは既存の設定を使用します。

## 検証

`tools/check-settings.ps1` は人工プロセスで、稼働中保存、再起動待ちの保持、管理画面を再度開いたときの読み戻し、終了時の書き戻し、ポート競合時の保持、次回起動前の反映、既存設定の保持を検証します。ホワイトリストは合成API応答でUUID・名前検証、重複排除、追加・解除、破損ファイル保持を確認します。実ユーザーへのAPI問い合わせ、本物のMinecraftでのログイン、実PCの距離性能測定はこのCIに含みません。
